# Microduck 项目概览

## 项目定位

Microduck 是一个约 25cm、800g 的双足机器人，由强化学习策略驱动。这个项目仓库是它的"大脑"——所有板端守护进程和控制软件的 Rust workspace。

## 核心能力

- **行走** — 手柄遥控，50Hz 控制循环驱动 15 个舵机
- **滚动** — 装上轮子切换策略（roller 模式）
- **捡东西** — 低头到地面一键完成
- **摔倒自恢复** — knocked over 后自己站起来
- **踢球** — 左右脚独立控制
- **翻滚** — 前滚翻（roulade）
- **坐下/站起** — sitstand 策略

## 硬件平台

| 组件 | 规格 |
|---|---|
| 主板 | Radxa Zero 3W (Rockchip RK3566, ARM64) |
| 内存 | 1 GB RAM |
| 存储 | 32 GB eMMC |
| 操作系统 | Armbian 26.2.1 Minimal |
| 舵机 | 15× XL330 (ROBOTIS Dynamixel) |
| IMU | imu_to_dxl v2 板 (LSM6DSV16X, 挂在 Dynamixel 总线) |
| WiFi/BT | aic8800 |
| ToF | VL53L5/VL53L8CX (I²C, 8×8 深度矩阵) |
| 摄像头 | 支持 V4L2 M2M 硬件编码 |
| NPU | Rockchip RKNN (RK3566 内置) |
| 电池 | NP-F550 (2600 mAh, ~1 小时续航) |

## 软件架构

7 个守护进程，全部用 Rust 编写：

| 守护进程 | 职责 |
|---|---|
| `robotd` | 控制循环 + Dynamixel 电机总线 + 策略推理 |
| `updaterd` | 签名更新、原子替换、健康检查、回滚 |
| `configd` | WiFi、身份配置 |
| `btd` | 蓝牙通道（手机 BLE 接入） |
| `padd` | 手柄读取 |
| `mediad` | 摄像头 WebRTC 推流 |
| `tofd` | 深度传感器 |

所有客户端（手机 app、手柄、笔记本、脚本）走同一套 JSON-RPC 契约。

## 技术栈

- **语言**: Rust 2024 edition (msrv 1.89)
- **异步运行时**: Tokio
- **推理引擎**: ONNX Runtime (`ort` crate)
- **NPU**: RKNN Runtime v2.3.2
- **媒体**: GStreamer + 自研硬件编码插件 (Rockchip MPP H.264 + WebRTC)
- **策略训练**: MuJoCo + PPO (隔壁仓库 microduck_rl)
- **通信协议**: JSON-RPC 2.0 over Unix socket (NDJSON)

```
microduck/
├── robotd/           # 控制守护进程
├── updater/          # 更新引擎 + updaterd
├── configd/          # 配置守护进程

├── padd/             # 手柄守护进程
├── mediad/           # 媒体守护进程
├── tof/              # ToF 守护进程
├── duck-control/     # 控制核心库（无 socket）

├── policies/         # ONNX 策略文件
```

## 关键设计原则

1. **安全层独占 IO** — 借用检查器强制，没有代码路径能绕过 safety 写电机
2. **服务拆分** — robotd 挂了还能通过 BLE 连上去更新/回滚
3. **单一 IPC 契约** — 所有客户端走同一套 API，不同传输层
4. **原子更新** — 签名验证 → 原子替换 → 健康门控 → 不健康自动回滚
5. **纯计算控制层** — 不持有 IO 句柄，只提议目标，safety 决定执行
