# 硬件架构

## 核心硬件平台

### 主板：Radxa Zero 3W

**SoC**: Rockchip RK3566
- **架构**: ARM64 (AArch64)
- **CPU**: 四核 Cortex-A55 @ 1.6GHz
- **GPU**: Mali-G52
- **NPU**: 0.8 TOPS (INT8)
- **内存**: 1GB LPDDR4
- **存储**: 32GB eMMC

**为什么选 RK3566？**
- 集成 NPU，可以跑 ONNX 模型推理
- 功耗低（~5W），适合电池供电
- 支持硬件视频编码（H.264/H.265）
- 成本适中（相比 Jetson 系列）

### 操作系统：Armbian 26.2.1 Minimal

**为什么选 Armbian？**
- 基于 Debian，软件生态成熟
- 针对 ARM 开发板优化
- 支持 device tree overlay
- 社区活跃，文档完善

**关键配置**
- 网络栈：NetworkManager（通过 D-Bus 控制）
- 日志系统：systemd-journald（持久化到 /var/log）
- 服务管理：systemd
- 用户空间：最小化安装，只保留必要组件

## 执行器系统

### Dynamixel XL330 舵机

**数量**: 15 个
**型号**: XL330-M288-T（推测，根据扭矩需求）

**关键参数**
- **电压**: 5-12V（项目使用 7.4V 锂电池）
- **扭矩**: 0.60 N·m @ 6V
- **分辨率**: 4096 pulse/rev (12-bit)
- **通信**: Dynamixel Protocol 2.0
- **波特率**: 1 Mbps
- **重量**: 18g

**关节分布**
```
左腿 (5个): ID 20-24
  - hip_yaw (20)
  - hip_roll (21)
  - hip_pitch (22)
  - knee (23)
  - ankle (24)

右腿 (5个): ID 10-14
  - hip_yaw (10)
  - hip_roll (11)
  - hip_pitch (12)
  - knee (13)
  - ankle (14)

头部 (5个): ID 30-34
  - neck_pitch (30)
  - head_pitch (31)
  - head_yaw (32)
  - head_roll (33)
  - mouth (34) - 不参与策略控制
```

**为什么选 Dynamixel？**
- **菊花链拓扑**: 一条总线串联所有舵机，简化布线
- **同步通信**: `sync_read` 一次读取所有舵机状态
- **内置 PID**: 每个舵机独立控制，减轻主控负担
- **反馈丰富**: 位置、速度、电流、温度、电压
- **生态成熟**: 开源库丰富（`rustypot`）

### 总线拓扑

```
/dev/ttyS2 (UART2, 1 Mbps)
    │
    ├─ ID 200: imu_to_dxl v2 (IMU 转接板)
    ├─ ID 20-24: 左腿舵机
    ├─ ID 10-14: 右腿舵机
    └─ ID 30-34: 头部舵机
```

**关键设计**
- **半双工通信**: TX/RX 共用一条线
- **主从架构**: 主控发送指令，舵机响应
- **同步读取**: 一次事务读取所有设备状态（~2ms）
- **同步写入**: 一次事务写入所有目标位置（~2ms）

**时序预算（50Hz 控制循环）**
```
总预算: 20ms
  - sync_read: ~2ms (16 个设备)
  - 策略推理: ~2ms (ONNX Runtime)
  - sync_write: ~2ms (15 个舵机)
  - 余量: ~14ms
```

## 传感器系统

### IMU: LSM6DSV16X

**位置**: 通过 imu_to_dxl v2 转接板挂在 Dynamixel 总线

**关键参数**
- **陀螺仪**: ±2000 dps，12-bit
- **加速度计**: ±16g，12-bit
- **采样率**: 100Hz（内部），50Hz（控制循环）
- **融合**: 内置 SFLP（Sensor Fusion Layer）
- **输出**: 四元数 + 角速度

**数据格式**
```rust
struct ImuData {
    gyro: [f64; 3],        // 角速度 (rad/s)
    gravity: [f64; 3],     // 重力方向（单位向量）
    quat: [f64; 4],        // 四元数 (w, x, y, z)
}
```

**为什么用转接板？**
- 统一通信协议（Dynamixel）
- 简化布线（和舵机共用一条总线）
- 同步采样（IMU 和舵机状态同时读取）

### ToF 传感器: VL53L5CX / VL53L8CX

**位置**: 头部，I²C 总线

**关键参数**
- **分辨率**: 8×8 像素
- **测距范围**: 0.2m - 4m
- **采样率**: 10-30Hz
- **接口**: I²C（400kHz）

**用途**
- 障碍物检测
- 深度估计（低分辨率）
- 辅助导航

**设计决策**
- **独立守护进程** (`tofd`): 不阻塞控制循环
- **发布-订阅模式**: 其他服务可以订阅深度数据
- **不进入策略**: 控制策略只用本体感受（proprioception）

### 摄像头

**接口**: CSI-2 或 USB（具体型号未指定）

**硬件编码**: Rockchip MPP (Media Process Platform)
- **编码格式**: H.264
- **分辨率**: 最高 1080p @ 30fps
- **码率**: 自适应（~2-4 Mbps）

**用途**
- 远程监控（WebRTC）
- 视觉感知（目标检测、跟踪）
- 录制回放

**设计决策**
- **硬件编码**: 减轻 CPU 负担
- **独立守护进程** (`mediad`): 媒体处理和机器人控制解耦
- **WebRTC 推流**: 低延迟远程访问

## 电源系统

### 电池

**型号**: NP-F550（相机电池）
- **电压**: 7.4V (2S Li-ion)
- **容量**: 2600 mAh
- **续航**: ~1 小时（取决于负载）

**电压监测**
```rust
// 通过舵机反馈监测电池电压
const BATTERY_FULL_V: f64 = 8.2;   // 满电电压
const BATTERY_EMPTY_V: f64 = 6.6;  // 截止电压

// 线性映射到百分比
fn battery_percent(volts: f64) -> f64 {
    ((volts - BATTERY_EMPTY_V) / (BATTERY_FULL_V - BATTERY_EMPTY_V))
        .clamp(0.0, 1.0) * 100.0
}
```

**低电量保护**
- **阈值**: 20%
- **动作**: 自动坐下，切断舵机电源
- **原因**: 防止电量耗尽导致摔倒

### 电源分配

```
电池 (7.4V)
  ├─ DC-DC 降压 → 5V (主板、舵机逻辑)
  └─ 直接供电 → 7.4V (舵机电机)
```

**为什么舵机直接用 7.4V？**
- 更高电压 = 更大扭矩
- 减少电流 = 减少线损
- 舵机支持宽电压范围（5-12V）

## 通信接口

### WiFi

**芯片**: aic8800
- **频段**: 2.4GHz / 5GHz
- **协议**: 802.11 b/g/n/ac
- **用途**: 远程访问、OTA 更新

### 蓝牙

**芯片**: aic8800（集成）
- **版本**: BLE 5.0
- **用途**: 手柄连接、手机配对

### USB

- **USB-C**: 供电、调试
- **USB 2.0**: 摄像头、外设

### I²C

- **设备**: ToF 传感器、IMU（通过转接板）
- **速率**: 400kHz

### UART

- **UART2**: Dynamixel 总线（舵机 + IMU）
- **波特率**: 1 Mbps

## 硬件设计亮点

### 1. 单总线设计

所有舵机和 IMU 共用一条 UART 总线：
- **简化布线**: 只需要 3 根线（TX、RX、GND）
- **同步采样**: IMU 和舵机状态同时读取
- **减少延迟**: 一次事务完成所有通信

### 2. 硬件加速

- **NPU**: 0.8 TOPS，跑 ONNX 推理
- **MPP**: 硬件视频编码
- **DMA**: 减少 CPU 干预

### 3. 模块化设计

- **独立守护进程**: 故障隔离
- **统一 IPC**: 松耦合
- **可替换组件**: 摄像头、ToF 可以没有

### 4. 成本优化

- **RK3566**: 相比 Jetson 便宜 50%+
- **XL330**: 相比 XM430 便宜 30%+
- **集成方案**: WiFi/BT/音频集成在一个芯片

## 硬件限制

### 1. 计算能力

- **CPU**: 四核 A55 @ 1.6GHz（中等）
- **内存**: 1GB（紧张）
- **NPU**: 0.8 TOPS（有限）

**应对策略**
- 策略模型轻量化（~1MB）
- 感知特征化（不传原始帧）
- 硬件编码（减轻 CPU 负担）

### 2. 续航

- **电池**: 2600 mAh（有限）
- **续航**: ~1 小时（较短）

**应对策略**
- 低功耗模式（空闲时降低 CPU 频率）
- 自动休眠（无操作 5 分钟后坐下）
- 可更换电池（NP-F550 通用）

### 3. 散热

- **被动散热**: 无风扇
- **温度限制**: CPU < 80°C，舵机 < 70°C

**应对策略**
- 温度监测（舵机内置传感器）
- 动态降频（过热时降低 CPU 频率）
- 保护机制（舵机过热自动断电）

## 总结

Microduck 的硬件设计体现了以下原则：

1. **成本优先**: 选择性价比高的组件
2. **集成度高**: 减少外部芯片，简化设计
3. **模块化**: 组件可替换，故障隔离
4. **实时性**: 单总线设计，同步采样
5. **低功耗**: 硬件加速，动态调节

这些设计决策使得 Microduck 能够在有限的硬件条件下实现复杂的双足行走和交互功能。
